# 要件定義書（システム共通基盤）

| 項目 | 内容 |
|------|------|
| 作成日 | 2026年5月28日 |
| バージョン | 1.0 |
| 対象 | Webシステム共通基盤（sys） |
| 技術スタック | TypeScript + Alpine.js + Bootstrap 5 + Python FastAPI |

---

## 1. 機能要件

### 1.1 認証・セッション管理

| ID | 要件 | 優先度 | 説明 |
|----|------|--------|------|
| FR-SYS-001 | ログイン機能 | 必須 | ユーザー名・パスワードによるログイン認証を提供する |
| FR-SYS-002 | ログアウト機能 | 必須 | セッションを破棄し、JWT Cookieを削除する |
| FR-SYS-003 | JWT発行・検証 | 必須 | httpOnly Cookieを使用したJWTトークン発行・検証機能を提供する |
| FR-SYS-004 | セッション管理 | 必須 | サーバーサイドセッションをJSONファイルで管理する（DAL経由） |
| FR-SYS-005 | セッション有効期限管理 | 必須 | JWTトークンの有効期限を検証し、期限切れの場合は再ログインを要求する |
| FR-SYS-006 | 自動ログアウト | 推奨 | 一定時間操作がない場合、自動的にログアウトする |

### 1.2 ユーザー管理

| ID | 要件 | 優先度 | 説明 |
|----|------|--------|------|
| FR-SYS-010 | ユーザー登録 | 必須 | 新規ユーザーを登録する（管理者権限） |
| FR-SYS-011 | ユーザー編集 | 必須 | ユーザー情報を編集する（管理者権限） |
| FR-SYS-012 | ユーザー削除 | 必須 | ユーザーを削除する（管理者権限） |
| FR-SYS-013 | ユーザー一覧表示 | 必須 | 全ユーザー一覧を表示する（管理者権限） |
| FR-SYS-014 | パスワード変更 | 必須 | 自分のパスワードを変更できる |
| FR-SYS-015 | 権限管理 | 必須 | ユーザーに管理者権限・一般ユーザー権限を設定する |

### 1.3 アプリプラグイン機構

| ID | 要件 | 優先度 | 説明 |
|----|------|--------|------|
| FR-SYS-020 | マニフェスト読み込み | 必須 | `apps/*/manifest.json` を自動読み込みし、アプリをシステムに登録する |
| FR-SYS-021 | アプリ自動認識 | 必須 | `apps/` ディレクトリに配置されたアプリを自動的に認識する |
| FR-SYS-022 | アプリ有効化・無効化 | 必須 | 管理画面からアプリを有効化・無効化できる |
| FR-SYS-023 | アプリ一覧表示 | 必須 | 登録済みアプリの一覧を表示する（名前・バージョン・ステータス） |
| FR-SYS-024 | アプリメタ情報管理 | 必須 | manifest.json に記載されたメタ情報（名前・バージョン・権限・エントリーポイント）を管理する |
| FR-SYS-025 | アプリ独立データ領域 | 必須 | 各アプリは `apps/<app-name>/backend/data/` に独立したデータ領域を持つ |
| FR-SYS-026 | アプリ間データ直接参照禁止 | 必須 | アプリは他のアプリのデータに直接アクセスできない |
| FR-SYS-027 | 無効化アプリアクセス拒否 | 必須 | 無効化されたアプリへのURL直接アクセスはシステムポータルページにリダイレクトする。APIエンドポイントアクセスは403エラーで拒否する |
| FR-SYS-028 | システムポータルページ | 必須 | ログイン後のランディングページとして機能し、有効化されたアプリ一覧をカード形式で表示する（アイコン・名前・説明・起動ボタンを含む）。システム情報（ユーザー名・権限・ログイン時刻）を表示する。URL: `/` または `/portal` |

### 1.4 共通API提供

| ID | 要件 | 優先度 | 説明 |
|----|------|--------|------|
| FR-SYS-030 | 認証API提供 | 必須 | アプリ向けに認証状態確認APIを提供する（`/api/sys/auth/me`） |
| FR-SYS-031 | ユーザー情報取得API | 必須 | ログイン中ユーザー情報を取得するAPIを提供する |
| FR-SYS-032 | 通知API提供 | 推奨 | アプリ向けに通知送信APIを提供する（SSE経由） |
| FR-SYS-033 | 共通設定API | 推奨 | システム共通設定を取得・更新するAPIを提供する |

### 1.5 共通UI部品提供

| ID | 要件 | 優先度 | 説明 |
|----|------|--------|------|
| FR-SYS-040 | ヘッダーコンポーネント | 必須 | ホームボタン・ログイン状態・ユーザー名・ログアウトボタンを含むヘッダーを提供する |

### 1.6 静的ファイル配信

| ID | 要件 | 優先度 | 説明 |
|----|------|--------|------|
| FR-SYS-050 | フロントエンド配信 | 必須 | FastAPIがビルド済みフロントエンド（`frontend/dist/`）を配信する |
| FR-SYS-051 | アプリフロントエンド配信 | 必須 | 各アプリのフロントエンド（`apps/*/frontend/dist/`）を配信する |
| FR-SYS-052 | SPAルーティング対応 | 必須 | フロントエンドのルーティングに対応し、リロード時も正常に動作する |

## 2. 非機能要件

### 2.1 セキュリティ

| ID | カテゴリ | 要件 | 基準値 |
|----|---------|------|--------|
| NFR-SYS-001 | 認証 | JWT（httpOnly Cookie）によるセキュアな認証を実装する | XSS攻撃によるトークン窃取を防止 |
| NFR-SYS-002 | CSRF対策 | CSRF対策（SameSite属性・CSRFトークン）を実装する | OWASP推奨基準に準拠 |
| NFR-SYS-003 | XSS防止 | 入力値のエスケープ・Content-Security-Policy設定を行う | OWASP推奨基準に準拠 |
| NFR-SYS-004 | パスワード保護 | パスワードをハッシュ化して保存する（bcrypt/Argon2） | ソルト付きハッシュ必須 |
| NFR-SYS-005 | HTTPS通信 | 本番環境ではHTTPS通信のみを許可する | TLS 1.2以上 |
| NFR-SYS-006 | SQL/NoSQLインジェクション対策 | DAL層でパラメータ化クエリを使用する | OWASP推奨基準に準拠 |
| NFR-SYS-007 | 認可チェック | API呼び出し時に権限チェックを実施する | 全APIエンドポイントで実施 |
| NFR-SYS-008 | ログ出力 | 認証失敗・権限エラーをログに記録する | セキュリティ監査可能 |

### 2.2 性能

| ID | カテゴリ | 要件 | 基準値 |
|----|---------|------|--------|
| NFR-SYS-010 | レスポンスタイム | REST APIは100ms以内にレスポンスを返す | 平均値（簡易データ取得） |
| NFR-SYS-011 | 同時接続数 | 最低10ユーザーの同時接続をサポートする | 初期目標値 |
| NFR-SYS-012 | SSEストリーム | リアルタイム通知を1秒以内に配信する | SSE接続確立済みの場合 |
| NFR-SYS-013 | フロントエンドビルドサイズ | システム共通基盤のJSバンドルサイズを500KB以下とする | gzip圧縮前 |

### 2.3 拡張性

| ID | カテゴリ | 要件 | 基準値 |
|----|---------|------|--------|
| NFR-SYS-020 | アプリ追加の容易性 | `apps/` ディレクトリに配置するだけでアプリを追加できる | 再起動のみで認識 |
| NFR-SYS-021 | アプリ独立性 | 各アプリは完全独立した構成（frontend/backend/tests/data）を持つ | 他アプリへの影響なし |
| NFR-SYS-022 | DAL抽象化 | データアクセス層（DAL）を抽象化し、RDB移行を容易にする | インターフェース統一 |
| NFR-SYS-023 | マニフェスト拡張性 | manifest.json に新しいフィールドを追加しても既存動作に影響しない | 後方互換性維持 |

### 2.4 保守性

| ID | カテゴリ | 要件 | 基準値 |
|----|---------|------|--------|
| NFR-SYS-030 | コーディング規約 | TypeScript・Python のコーディング規約に準拠する | Prettier・Black使用 |
| NFR-SYS-031 | テストカバレッジ | 単体テストカバレッジ80%以上を維持する | 重要機能は100% |
| NFR-SYS-032 | ドキュメント整備 | API仕様書・設計書を常に最新化する | Markdown形式 |
| NFR-SYS-033 | エラーハンドリング | 全APIでエラーハンドリングを実装し、適切なHTTPステータスコードを返す | 500エラー最小化 |

### 2.5 可用性

| ID | カテゴリ | 要件 | 基準値 |
|----|---------|------|--------|
| NFR-SYS-040 | エラー復旧 | アプリの障害がシステム全体に影響しない | 各アプリは独立動作 |
| NFR-SYS-041 | データバックアップ | JSONデータを定期的にバックアップする機能を提供する | 日次バックアップ推奨 |
| NFR-SYS-042 | ログ保持 | システムログを30日間保持する | ローテーション設定 |

### 2.6 移行性

| ID | カテゴリ | 要件 | 基準値 |
|----|---------|------|--------|
| NFR-SYS-050 | RDB移行対応 | DAL抽象化により、JSON DBからRDBへの移行を可能にする | インターフェース統一 |
| NFR-SYS-051 | データエクスポート | JSONデータをエクスポートする機能を提供する | 全データ対応 |
| NFR-SYS-052 | データインポート | JSONデータをインポートする機能を提供する | 全データ対応 |

## 4. インターフェース要件

### 4.1 REST API

| 項目 | 要件 |
|------|------|
| データフォーマット | JSON |
| エラーレスポンス | `{"error": "エラーメッセージ", "code": "ERROR_CODE"}` |
| 認証ヘッダー | Cookie（httpOnly、JWT） |
| CORS対応 | 開発環境のみ許可 |

### 4.2 SSE（Server-Sent Events）

| 項目 | 要件 |
|------|------|
| 用途 | リアルタイム通知・進捗配信 |
| エンドポイント | `/api/sys/notifications/stream` |
| イベント形式 | `event: <type>\ndata: <json>\n\n` |

## 5. データ要件

### 5.1 システムデータ

| データ種別 | 格納場所 | 説明 |
|-----------|---------|------|
| ユーザー情報 | `backend/data/users.json` | ユーザーID・パスワードハッシュ・権限 |
| セッション情報 | `backend/data/sessions/` | JWT検証用セッションデータ |
| アプリ設定 | `backend/data/apps.json` | アプリ有効化状態・設定情報 |
| システム設定 | `backend/data/config.json` | システム全体の設定 |

### 5.2 データアクセス層（DAL）

| 項目 | 要件 |
|------|------|
| インターフェース統一 | JSON DB・RDBで同一のインターフェースを提供する |
| トランザクション対応 | JSON DBでは疑似トランザクション（ロック機構）を実装する |
| 検索・フィルタ | 基本的なCRUD操作・検索・フィルタ機能を提供する |

## 7. 対象外事項

以下は本工程の対象外とする：

- WebSocketによる双方向リアルタイム通信（将来検討）
- AI機能の詳細仕様（アプリ側で定義）
- RDB実装の詳細（DAL抽象化のみ対応）
- 多言語対応（国際化・ローカライゼーション）
- モバイルアプリ対応
