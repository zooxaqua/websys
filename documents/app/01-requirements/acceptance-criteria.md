## 1. アプリ構成

### AC-APP-001: 完全独立構成（FR-APP-001, UC-APP-008）

| 項目 | 合否条件 |
|------|----------|
| **ディレクトリ構成** | 各アプリが `frontend/`, `backend/`, `tests/`, `data/` を持つ |
| **独立動作** | アプリが他のアプリに依存せず動作する |
| **影響なし** | 1つのアプリの障害が他のアプリに影響しない |

### AC-APP-002: manifest.json定義（FR-APP-002, UC-APP-001）

| 項目 | 合否条件 |
|------|----------|
| **必須フィールド** | `name`, `displayName`, `version`, `description`, `entryPoint`, `apiPrefix` が記載されている |
| **形式検証** | manifest.jsonが正しいJSON形式である |
| **自動登録** | システム起動時にmanifest.jsonが読み込まれ、アプリが登録される |

### AC-APP-003: エントリーポイント定義（FR-APP-003, UC-APP-001）

| 項目 | 合否条件 |
|------|----------|
| **正常遷移** | ナビゲーションメニューからアプリをクリックすると、`entryPoint` に遷移する |
| **ビルド成果物** | `frontend/dist/` にビルドされたフロントエンドが配置されている |

## 2. システム共通基盤連携

### AC-APP-010: 認証API利用（FR-APP-010, UC-APP-002）

| 項目 | 合否条件 |
|------|----------|
| **正常系** | `/api/sys/auth/me` を呼び出してユーザー情報を取得できる |
| **異常系** | JWT Cookieが無効な場合、401 Unauthorizedが返される |
| **リダイレクト** | 認証エラー時、ログイン画面にリダイレクトされる |

### AC-APP-011: 共通UI部品利用（FR-APP-011, UC-APP-006）

| 項目 | 合否条件 |
|------|----------|
| **ヘッダー表示** | システム共通基盤のヘッダーが表示される |
| **ナビゲーション表示** | システム共通基盤のナビゲーションメニューが表示される |
| **統一スタイル** | Bootstrap 5のスタイルで統一されたUIが表示される |

### AC-APP-012: 通知API利用（FR-APP-012, UC-APP-007）

| 項目 | 合否条件 |
|------|----------|
| **通知送信** | アプリが `/api/sys/notifications/send` を呼び出して通知を送信できる |
| **SSE配信** | 通知がSSE経由でフロントエンドに配信される |
| **トースト表示** | 通知がトースト形式で表示される |

## 3. データ管理

### AC-APP-020: 独立データ領域（FR-APP-020, UC-APP-003, UC-APP-004）

| 項目 | 合否条件 |
|------|----------|
| **保存** | アプリのデータが `apps/<app-name>/backend/data/` に保存される |
| **読み込み** | アプリのデータが `apps/<app-name>/backend/data/` から読み込める |
| **独立性** | 各アプリのデータが他のアプリから隔離されている |

### AC-APP-021: DAL利用（FR-APP-021, UC-APP-003, UC-APP-004）

| 項目 | 合否条件 |
|------|----------|
| **DAL経由** | データの読み書きがDAL経由で行われる |
| **トランザクション** | 同時書き込み時にファイルロックが機能する |

### AC-APP-022: 他アプリデータ直接参照禁止（FR-APP-022, UC-APP-005）

| 項目 | 合否条件 |
|------|----------|
| **アクセス拒否** | アプリが他のアプリのデータ領域にアクセスすると、403 Forbiddenが返される |
| **ログ記録** | 不正アクセス試行がログに記録される |

## 9. TODO機能

### AC-TODO-001: TODO追加（FR-TODO-001, UC-TODO-001）

| 項目 | 合否条件 |
|------|----------|
| **正常系** | ユーザーが新しいTODOを追加できる |
| **異常系** | タイトルが空の場合、エラーメッセージが表示される |
| **保存** | TODOが `apps/todo-app/backend/data/todos.json` に保存される |
| **表示** | 追加したTODOが一覧に表示される |

### AC-TODO-002: TODO一覧表示（FR-TODO-002, UC-TODO-002）

| 項目 | 合否条件 |
|------|----------|
| **正常系** | ユーザーのTODO一覧が表示される |
| **空の場合** | TODOがない場合、「TODOがありません」と表示される |
| **自分のTODOのみ** | ユーザーは自分のTODOのみ表示される |

### AC-TODO-003: TODO編集（FR-TODO-003, UC-TODO-003）

| 項目 | 合否条件 |
|------|----------|
| **正常系** | ユーザーがTODOを編集できる |
| **異常系** | 存在しないTODOを編集しようとすると、404 Not Foundが返される |
| **更新** | 編集内容が `apps/todo-app/backend/data/todos.json` に保存される |
| **表示** | 編集したTODOが一覧に反映される |

### AC-TODO-004: TODO削除（FR-TODO-004, UC-TODO-004）

| 項目 | 合否条件 |
|------|----------|
| **正常系** | ユーザーがTODOを削除できる |
| **確認ダイアログ** | 削除前に確認ダイアログが表示される |
| **削除** | TODOが `apps/todo-app/backend/data/todos.json` から削除される |
| **表示** | 削除したTODOが一覧から消える |

### AC-TODO-005: TODO完了/未完了切り替え（FR-TODO-005, UC-TODO-005）

| 項目 | 合否条件 |
|------|----------|
| **正常系** | ユーザーがTODOの完了状態を切り替えできる |
| **表示** | 完了済みTODOは打ち消し線が表示される |
| **更新** | 完了状態が `apps/todo-app/backend/data/todos.json` に保存される |

### AC-TODO-006: TODOフィルタ表示（FR-TODO-006）

| 項目 | 合否条件 |
|------|----------|
| **全て表示** | 「全て」を選択すると、全TODOが表示される |
| **未完了のみ** | 「未完了」を選択すると、未完了TODOのみ表示される |
| **完了済みのみ** | 「完了済み」を選択すると、完了済みTODOのみ表示される |

### AC-TODO-007: TODO検索（FR-TODO-007）

| 項目 | 合否条件 |
|------|----------|
| **タイトル検索** | 検索キーワードがタイトルに含まれるTODOが表示される |
| **内容検索** | 検索キーワードが内容に含まれるTODOが表示される |
| **検索結果0件** | 該当するTODOがない場合、「検索結果がありません」と表示される |
