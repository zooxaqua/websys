## UC-APP-001: アプリの起動

### アクター
- 一般ユーザー / 管理者

### 前提条件
- ユーザーがログイン状態である
- 対象アプリが有効化されている

### 正常系
1. ユーザーがナビゲーションメニューからアプリを選択する
2. システムはmanifest.jsonの `entryPoint` を読み取る
3. システムは該当アプリのフロントエンドにリダイレクトする
4. フロントエンドは `/api/sys/auth/me` を呼び出してユーザー情報を取得する
5. アプリ画面が表示される

### 代替系
- **2a. manifest.jsonが不正**
  - 2a1. システムは「アプリを読み込めませんでした」とエラーメッセージを表示する
- **4a. JWT Cookieが無効**
  - 4a1. システムはログイン画面にリダイレクトする

### 事後条件
- アプリが起動し、ユーザーが利用可能となる

### 関連要件
- FR-APP-001, FR-APP-003, FR-APP-010

## UC-APP-002: アプリ固有APIの呼び出し

### アクター
- アプリのフロントエンド（TypeScript）

### 前提条件
- ユーザーがログイン状態である
- アプリが起動している

### 正常系
1. フロントエンドが `/api/<app-name>/<endpoint>` にリクエストを送信する
2. バックエンドはJWT Cookieを検証する
3. バックエンドはユーザー情報を取得する
4. バックエンドは処理を実行し、結果をJSONで返す
5. フロントエンドは結果を受け取り、画面を更新する

### 代替系
- **2a. JWT Cookieが無効**
  - 2a1. バックエンドは401 Unauthorizedを返す
  - 2a2. フロントエンドはログイン画面にリダイレクトする
- **3a. 権限不足**
  - 3a1. バックエンドは403 Forbiddenを返す
  - 3a2. フロントエンドはエラーメッセージを表示する

### 事後条件
- API処理が実行され、結果がフロントエンドに返される

### 関連要件
- FR-APP-041, FR-APP-042, FR-APP-043

## UC-APP-003: アプリデータの保存

### アクター
- アプリのバックエンド（FastAPI）

### 前提条件
- ユーザーがログイン状態である
- アプリが起動している

### 正常系
1. フロントエンドがデータ保存APIを呼び出す
2. バックエンドはJWT Cookieを検証する
3. バックエンドはDAL経由でデータを `apps/<app-name>/backend/data/` に保存する
4. バックエンドは成功レスポンスを返す
5. フロントエンドは「保存しました」とメッセージを表示する

### 代替系
- **3a. データ保存に失敗**
  - 3a1. バックエンドは500 Internal Server Errorを返す
  - 3a2. エラーログに詳細を記録する
  - 3a3. フロントエンドは「保存に失敗しました」とエラーメッセージを表示する

### 事後条件
- データが `apps/<app-name>/backend/data/` に保存される

### 関連要件
- FR-APP-020, FR-APP-021

## UC-APP-005: 他アプリデータへのアクセス拒否

### アクター
- アプリのバックエンド（FastAPI）

### 前提条件
- アプリが起動している

### 正常系
1. アプリAのバックエンドが他のアプリBのデータ領域（`apps/app-b/backend/data/`）へのアクセスを試みる
2. DALはアクセス元アプリを検証する
3. DALはアクセスを拒否し、403 Forbiddenを返す
4. エラーログに不正アクセス試行を記録する

### 代替系
- なし

### 事後条件
- 他アプリのデータへのアクセスが拒否される
- 不正アクセス試行がログに記録される

### 関連要件
- FR-APP-022

## UC-APP-008: アプリのビルド・デプロイ

### アクター
- アプリ開発者

### 前提条件
- アプリのソースコードが完成している

### 正常系
1. アプリ開発者がフロントエンドをViteでビルドする（`npm run build`）
2. ビルド成果物が `frontend/dist/` に出力される
3. アプリ開発者がバックエンドの依存関係をインストールする（`pip install -r requirements.txt`）
4. アプリ開発者がアプリディレクトリを `apps/<app-name>/` に配置する
5. システム共通基盤が manifest.json を読み込み、アプリを登録する
6. 管理者がアプリを有効化する
7. ユーザーがナビゲーションメニューからアプリにアクセスできるようになる

### 代替系
- **2a. ビルドエラー**
  - 2a1. エラーメッセージを確認し、ソースコードを修正する
- **5a. manifest.jsonが不正**
  - 5a1. エラーログを確認し、manifest.jsonを修正する

### 事後条件
- アプリがデプロイされ、ユーザーが利用可能となる

### 関連要件
- FR-APP-001, FR-APP-002, FR-APP-033

## UC-TODO-001: TODO追加

### アクター
- 一般ユーザー

### 前提条件
- ユーザーがログイン状態である
- TODOアプリが起動している

### 正常系
1. ユーザーが「新規TODO」ボタンをクリックする
2. ユーザーがタイトル・内容を入力する
3. ユーザーが「追加」ボタンをクリックする
4. フロントエンドが `/api/todo-app/todos` にPOSTリクエストを送信する
5. バックエンドはTODOを `apps/todo-app/backend/data/todos.json` に保存する
6. バックエンドは成功レスポンスを返す
7. フロントエンドは「TODOを追加しました」とメッセージを表示する
8. TODO一覧が更新される

### 代替系
- **3a. タイトルが空**
  - 3a1. フロントエンドは「タイトルを入力してください」とエラーメッセージを表示する

### 事後条件
- 新しいTODOが保存される
- TODO一覧に表示される

### 関連要件
- FR-TODO-001

## UC-TODO-003: TODO編集

### アクター
- 一般ユーザー

### 前提条件
- ユーザーがログイン状態である
- 編集対象のTODOが存在する

### 正常系
1. ユーザーがTODOの「編集」ボタンをクリックする
2. ユーザーがタイトル・内容を変更する
3. ユーザーが「保存」ボタンをクリックする
4. フロントエンドが `/api/todo-app/todos/<id>` にPUTリクエストを送信する
5. バックエンドはTODOを更新し、`apps/todo-app/backend/data/todos.json` に保存する
6. バックエンドは成功レスポンスを返す
7. フロントエンドは「TODOを更新しました」とメッセージを表示する
8. TODO一覧が更新される

### 代替系
- **4a. 対象TODOが見つからない**
  - 4a1. バックエンドは404 Not Foundを返す
  - 4a2. フロントエンドは「TODOが見つかりませんでした」とエラーメッセージを表示する

### 事後条件
- TODOが更新される
- 変更内容が画面に反映される

### 関連要件
- FR-TODO-003

  - 3a2. フロントエンドは「TODOが見つかりませんでした」とエラーメッセージを表示する
